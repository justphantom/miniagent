# 记忆文件反过期规则：数量/清单引用用指针，不硬编码

## 背景
`.agent` 记忆文件描述代码结构时，硬编码数量（如「`LoopHooks` 8 个函数字段」）随代码演进悄然过期——v4.3.0 加 `OnStep` 后实为 9 个，L0/L2 三处仍写 8，全量评审才被发现。代码有编译器与测试兜底，记忆文件没有。

## 规则
1. **描述代码结构数量 / 成员清单时，优先指指针**：写「见 `internal/miniagent/loop_api.go`」而非「N 个字段」。若数量本身是论述要点（如对比前后），写法为「现 N 个，见 `loop_api.go`」，便于核验。
2. **必须硬编码时**：改动代码对应结构（加 hook 字段、增 config 旋钮、改枚举）的同一任务内，同步 grep `.agent/` 中相关描述并更新——改动落点检查（L0 policies #5）扩展到记忆目录。
3. **版本状态标注成对更新**：条目记「未实施 / 待修」的根治方向，修复发版时同步改状态，避免条目内部自相矛盾（如顶部「已修」+ 小节「未实施」）。
4. **评审兜底**：发版或大改后对 `.agent/` 跑一次引用核验（文件路径存在性 + commit hash + 关键数字抽查）。
